# A repeated week gives unlogged workouts new dates

Results are saved under a workout's date, so a week run a second time needs an identity of its own. Instead of splitting a workout's identity from its date, which every saved result, screen and test relies on, the calendar is worked out from `repeat:<start>` events in the synced history: dates before the start keep their workouts, and from the start on the program runs again from the chosen week, each workout on its new date. This holds only while nothing is logged from that start on, because a date's results belong to the workout it held; so a repeat can start only after everything logged, and undoing one is refused once its dates have results. Slid workouts therefore take new original dates, unlike moved workouts, which keep theirs. Repeats start on the week's own weekday so roadmap notes such as "Saturday is your 4-mile run" stay true. Holiday names came out of program data, since any slide would leave them on the wrong day. The database's entity check had to admit `repeat:`, so this needed a migration that must run before the app is used to repeat a week.
