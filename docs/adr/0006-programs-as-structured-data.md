# Store each program as structured data converted from its roadmap

Each program is stored as structured data (sections, exercises, sets, targets, units, rest, sides and tempo) with the roadmap's original wording kept for display, instead of being parsed from roadmap text while the app runs. Roadmaps are written by Claude in prose that changes from one program to the next, so a runtime parser keeps growing special cases and can misread a set count or unit without any error; converting each roadmap once, with checks, catches those mistakes and surfaces ambiguities while they can still be asked about. Exercises point into one shared exercise list so history carries across programs, and saved results refer to sections and exercises by ID, so those IDs never change once results exist; the current program's data is generated from the old parser's output to keep the IDs its history already uses.
